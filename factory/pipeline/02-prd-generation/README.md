# Stage 02: PRD Generation

## What Happens Here

Take the clean idea summary from Stage 01 and turn it into a real Product Requirements Document.

**Input:** Structured idea summary with core concept, audience, and features.

**Output:** A complete PRD with user stories, feature specs, success criteria, and scope boundaries.

## What Gets Mounted Here

- Feature requirements that need to be formalized
- User story templates for specific app types
- Scope definition prompts
- MVP vs full-build decision frameworks

## The Prompts

Prompts in this stage guide the AI to:
1. Define the product vision in one sentence
2. Write user stories for each feature
3. Set clear scope boundaries (what's in, what's out)
4. Define success criteria (how do you know it works?)
5. Prioritize features (must-have vs nice-to-have)
6. Identify technical constraints or dependencies

## When Is This Stage Done?

When you have a document that a developer could pick up and know exactly what to build, in what order, and how to verify it works.
