# Skill Template — Quality Reference

> Use this template to review every generated skill for consistency and completeness.
> You do NOT write skills from this template — Context7 generates them.
> You compare the generated output against this template to make sure nothing is missing.

---

## Required Format

Every skill file must follow this structure. If a generated skill is missing a section, add it manually before saving.

---

### Header Block

The very top of every skill file must have this metadata block:

```markdown
# {Library Name} — Claude Code Skill

> **Library:** {library-name}
> **Version:** {version number the skill was generated against}
> **Generated:** {YYYY-MM-DD}
> **Source:** Context7 — live documentation pull
> **Category:** {category from the master list}
> **Boilerplates:** {web, mobile, dual, or universal}
```

**Example:**

```markdown
# Next.js App Router — Claude Code Skill

> **Library:** next
> **Version:** 16.2.0
> **Generated:** 2026-04-06
> **Source:** Context7 — live documentation pull
> **Category:** frameworks
> **Boilerplates:** web, dual
```

### Section 1: Overview

A 2-4 sentence summary of what this library does and when to use it. Written for Claude Code, not for a human tutorial.

**What to check for:**
- Is it concise? (No more than 4 sentences)
- Does it say what the library IS, not just what it does?
- Does it mention the version or major paradigm?

**Example:**

```markdown
## Overview

Next.js 16 is a React framework for production web applications. Use the App Router (not Pages Router) for all new development. It provides server components by default, server actions for mutations, and file-based routing with layouts and loading states.
```

---

### Section 2: Core Patterns

The main section. This is where the actual patterns, code examples, and best practices live. This should be the longest section.

**What to check for:**
- Are the patterns CURRENT for the stated version? (Not deprecated APIs)
- Are code examples included for each pattern?
- Are the examples minimal but complete? (Not 50-line monsters, but not pseudocode either)
- Do the patterns cover the most common use cases?
- Are file paths shown where relevant? (e.g., `app/layout.tsx`)

**Structure within this section:**

```markdown
## Core Patterns

### {Pattern Name}

{1-2 sentence explanation}

```{language}
{code example}
```

### {Pattern Name}

...
```

**Minimum patterns to cover per skill:**
- The basic setup / initialization
- The most common operation (e.g., CRUD for databases, routing for frameworks)
- Error handling
- At least one advanced pattern (e.g., middleware, streaming, caching)

---

### Section 3: Common Pitfalls

A bulleted list of mistakes Claude Code should avoid. These are the "gotchas" that waste time.

**What to check for:**
- At least 3 pitfalls listed
- Each one is specific (not vague like "be careful with state")
- Each one says what TO DO, not just what not to do

**Example:**

```markdown
## Common Pitfalls

- **Do NOT use `useEffect` for data fetching in server components.** Server components fetch data directly in the component body. `useEffect` only runs on the client.
- **Do NOT import server-only modules in client components.** Mark server-only code with `'use server'` or use the `server-only` package.
- **Always add `'use client'` at the top of files that use hooks, event handlers, or browser APIs.** Without this directive, Next.js treats the component as a server component and it will fail.
```

---

### Section 4: Integration Notes

How this library connects with other libraries in the stack. This is especially important for skills that are part of the same boilerplate.

**What to check for:**
- Does it mention relevant companion libraries? (e.g., "works with Supabase Auth for SSR")
- Does it note any version conflicts or compatibility requirements?
- Does it mention environment variables that need to be set?

**Example:**

```markdown
## Integration Notes

- **Supabase:** Use `@supabase/ssr` for server-side auth in App Router. Create the client in a server utility, not in each component.
- **Stripe:** Server actions are the preferred way to create Stripe checkout sessions. Do not expose the secret key in client components.
- **Tailwind CSS v4:** Import the CSS file in `app/layout.tsx`. The v4 config uses `@theme` in CSS, not `tailwind.config.js`.
```

### Footer Block

The very bottom of every skill file:

```markdown
---

*Generated by Context7 on {YYYY-MM-DD}. Patterns reflect {library-name} v{version}. Regenerate if the library ships breaking changes.*
```

## Quality Checklist

Run through this for every generated skill before saving it:

- [ ] **Header block** is present with all 6 fields filled in
- [ ] **Overview** is 2-4 sentences, mentions the library version
- [ ] **Core Patterns** has at least 4 patterns with code examples
- [ ] **Code examples** use the correct language tag (tsx, ts, dart, python, etc.)
- [ ] **Code examples** are current for the stated version (no deprecated APIs)
- [ ] **Common Pitfalls** has at least 3 specific, actionable items
- [ ] **Integration Notes** mentions at least 2 companion libraries
- [ ] **Footer block** is present with correct date and version
- [ ] **File is saved** in the correct category folder with the correct kebab-case filename
- [ ] **No marketing language** — this is a technical reference, not a sales pitch
- [ ] **No placeholders** — every `{placeholder}` has been replaced with real content

## Filename Convention

All skill files use kebab-case with `.md` extension:

```
next-js-app-router.md
supabase-auth.md
tailwind-css-v4.md
react-native-expo.md
```

The filename must match the skill name in `MASTER-SKILL-LIST.md` exactly.
