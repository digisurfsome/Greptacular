# Video-to-Social System — PRD
> Standalone. Input-agnostic. Anything promotable → rendered video → 7 platforms.

---

## What This System Is

A pipeline that takes a structured content brief (from any source), selects a video template, injects content into it, renders an MP4, and distributes to all connected social platforms automatically. The input source is irrelevant — YouTube transcript, app info, chaos engine JSON, podcast clip, product launch, anything. Same pipeline every time.

## How a Template Is Actually Structured

From reading the real Hyperframes code, every template is a self-contained folder:

```
video-projects/
└── {template-slug}/
    ├── index.html              ← root conductor (orchestrates beats, no animation logic here)
    ├── meta.json               ← id, title, width, height, fps
    ├── hyperframes.json        ← CLI config (paths)
    ├── compositions/           ← one HTML file per beat
    │   ├── 01-hook.html
    │   ├── 02-problem.html
    │   ├── 03-content-a.html
    │   ├── 04-content-b.html
    │   ├── 05-content-c.html
    │   ├── 06-destruction.html   ← or product-reveal for non-chaos templates
    │   ├── 07-demo.html
    │   └── 08-cta-outro.html
    ├── assets/
    │   ├── brand-tokens.css    ← CSS custom props (colors, fonts, logo path)
    │   ├── logo.png
    │   ├── narration.wav       ← generated by TTS at render time
    │   ├── bg-music.mp3        ← optional ambient track
    │   └── sfx/                ← transition sound effects
    ├── renders/                ← gitignored, local output scratch
    └── TEMPLATE.md             ← token map + slot descriptions
```

### How `index.html` Works (The Conductor)

The root file does one thing: lists beats in order with timing. It contains no animation logic — that all lives in each composition file.

```html
<div id="root" data-composition-id="hardware-hack-30s"
     data-start="0" data-duration="30"
     data-width="1080" data-height="1920">

  <!-- Each beat is a div that loads an external HTML file -->
  <div class="beat"
       data-composition-src="compositions/01-hook.html"
       data-composition-id="01-hook"
       data-start="0" data-duration="3"
       data-track-index="0"
       data-width="1080" data-height="1920"></div>

  <div class="beat"
       data-composition-src="compositions/02-hack.html"
       data-composition-id="02-hack"
       data-start="3" data-duration="5"
       data-track-index="0"
       data-width="1080" data-height="1920"></div>

  <!-- ... more beats ... -->

  <!-- Audio tracks alongside beats -->
  <audio data-start="0" data-duration="30" data-track-index="1"
         data-volume="0.15" src="assets/bg-music.mp3"></audio>
  <audio data-start="0" data-duration="30" data-track-index="2"
         data-volume="1.0"  src="assets/narration.wav"></audio>
</div>

<script>
  window.__timelines = window.__timelines || {};
  const tl = gsap.timeline({ paused: true });
  tl.to({}, { duration: 30 }, 0);   // hollow placeholder — CLI owns playback
  window.__timelines["hardware-hack-30s"] = tl;
</script>
```

### How a Beat File Works (e.g. `01-hook.html`)

Each beat is a fully self-contained HTML file with its own GSAP timeline. It has **token placeholders** that get replaced before render.

```html
<!doctype html>
<html>
<head>
  <script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/gsap.min.js"></script>
  <link rel="stylesheet" href="../../assets/brand-tokens.css">
  <style>
    body { width: 1080px; height: 1920px; background: #000; }
    .hook-text { font: 700 96px var(--brand-font); color: var(--brand-accent); }
  </style>
</head>
<body>
  <div id="root" data-composition-id="01-hook"
       data-start="0" data-duration="3"
       data-width="1080" data-height="1920">

    <div class="hook-text clip"
         data-start="0" data-duration="3" data-track-index="0">
      {{HOOK}}
    </div>

  </div>
  <script>
    window.__timelines = window.__timelines || {};
    const tl = gsap.timeline({ paused: true });
    // animation logic here
    gsap.set(".hook-text", { opacity: 0, y: 60 });
    tl.to(".hook-text", { opacity: 1, y: 0, duration: 0.4, ease: "expo.out" }, 0);
    window.__timelines["01-hook"] = tl;
  </script>
</body>
</html>
```

### Token Map (`TEMPLATE.md`)

Every template ships with a token map that documents every slot:

```
{{HOOK}}           — Opening line. Max 8 words. Pattern interrupt.
{{PROBLEM_LINE}}   — What the viewer is suffering from. 1 sentence.
{{POINT_1}}        — First content beat. Max 12 words.
{{POINT_2}}        — Second content beat. Max 12 words.
{{POINT_3}}        — Third content beat. Max 12 words.
{{CTA_LINE}}       — Call to action. Max 6 words.
{{PRODUCT_NAME}}   — Brand/product name. Used in outro.
{{CTA_URL}}        — Link shown in outro.
{{BRAND_COLOR}}    — Pulled from brand-tokens.css automatically.
{{VOICE_ID}}       — TTS voice for narration (e.g. am_adam).
```

## Adding a New Template — Step by Step

### Step 1 — Intake (Fill the Template Brief)
Before touching code, complete the intake form (see section below). This produces a `brief.json` that drives everything downstream.

### Step 2 — Create the Folder
```bash
mkdir video-projects/{template-slug}
mkdir video-projects/{template-slug}/compositions
mkdir video-projects/{template-slug}/assets
```

### Step 3 — Write `meta.json`
```json
{
  "id": "hardware-hack-30s",
  "title": "Hardware Hack — 30s Chaos Commercial",
  "width": 1080,
  "height": 1920,
  "fps": 30
}
```

### Step 4 — Write the Beat Map
Lay out every beat with its duration before writing any HTML. Beats must add up to total duration.

```
Beat 01  0:00–0:03   Hook opener (3s)
Beat 02  0:03–0:08   Hardware hack applied (5s)
Beat 03  0:08–0:16   Absurd rationale + escalation (8s)
Beat 04  0:16–0:22   Destruction (6s)
Beat 05  0:22–0:25   Product flash reveal (3s)
Beat 06  0:25–0:28   Product demo (3s)
Beat 07  0:28–0:30   CTA outro — holds 4s min (2s)  ← extend if needed
```

### Step 5 — Build `index.html`
Wire up beats using the conductor pattern shown above. Add audio tracks. Register the master timeline.

### Step 6 — Build Each Beat Composition
One HTML file per beat. Every beat:
- Has its own `window.__timelines["beat-id"]` registration
- Uses `{{TOKEN}}` placeholders for any text content
- Imports `../../assets/brand-tokens.css`
- Includes its own GSAP `<script>` tag (GSAP does not inherit from parent)
- Uses `class="clip"` on all timed elements (except `<video>` and `<audio>`)

### Step 7 — Run the Registry Blocks
Install needed catalog blocks:
```bash
npx hyperframes add grain-overlay
npx hyperframes add whip-pan
npx hyperframes add tiktok-follow
npx hyperframes add flash-through-white
```

### Step 8 — Write `TEMPLATE.md`
Document every `{{TOKEN}}` — name, description, max length, which beat it appears in.

### Step 9 — Lint, Preview, Render Target
```bash
npx hyperframes lint
npx hyperframes preview          # verify at localhost:3002
npx hyperframes render --quality draft --output renders/draft.mp4
# verify frames, fix issues
npx hyperframes render --quality standard --output renders/final.mp4
```

`final.mp4` = the target. This is what the automation system tries to reproduce when filling in real content.

## The Automation Pipeline (Input-Agnostic)

```
ANY INPUT SOURCE
     │
     ▼
[Content Brief]          ← structured JSON regardless of source
     │
     ▼
[Haiku: Script Gen]      ← reads brief + template token map → fills tokens
     │
     ▼
[Token Injector]         ← reads base template HTML, replaces {{TOKENS}}, writes to temp dir
     │
     ▼
[TTS Generator]          ← npx hyperframes tts "narration text" --voice {voice_id}
     │                      outputs narration.wav + word-level timestamps
     ▼
[Caption Sync]           ← timestamps → karaoke caption composition
     │
     ▼
[Lint + Render]          ← npx hyperframes lint && npx hyperframes render
     │                      ~2 min → final.mp4
     ▼
[User Approval]          ← notification + thumbnail preview, tap to post
     │                      (auto-approve available on Pro)
     ▼
[Caption Gen]            ← Haiku writes platform-specific caption × 7 platforms
     │
     ▼
[Late API Post]          ← single call → TikTok, Instagram, YouTube, LinkedIn,
                            X, Facebook, Threads (+ 6 more available)
```

### Input Sources (All Feed the Same Pipeline)

| Source | Brief Type | Haiku Task |
|--------|-----------|------------|
| YouTube URL | Worksheet: headline, steps, hook, affiliate link | Educational short-form template |
| App info form | Product brief: name, features, user, tone, CTA | Commercial or feature reveal template |
| Chaos Engine | Mix-up JSON: hack + rationale + format + destruction | Hardware hack / chaos commercial template |
| Protocol content | Rules, timing, steps | Educational vertical template |
| Podcast clip | Transcript segment + key point | Short-form quote/clip template |
| Product launch | Launch brief: name, date, features, price | App release / hype film template |
| Blog post URL | Post content → scraped → summarized | Educational lesson template |
